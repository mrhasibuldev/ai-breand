## 2. Check 1 — Parameter Count Discrepancy

### Investigation

**Question**: Why does `current.json` report 4,776,522 parameters while checkpoint loading reports 4,907,594?

### Measurements

**Actual Model Parameter Count** (using reconstructed MediumTransformer with fixed imports):
- Instantiated MediumTransformer with vocab_size=74, d_model=256, n_layers=6, n_heads=8, d_ff=1024, max_len=512
- `model.count_parameters()`: **4,776,522**

**Checkpoint State Dictionary Parameter Count**:
- Loaded `final_model.pt` checkpoint
- Sum of all parameters in `model_state_dict`: **4,907,594**

**Positional Encoding Buffer Size**:
- `positional_encoding.pe` buffer: **131,072** elements (512 × 256)
- This is a `register_buffer`, not a trainable parameter

**Calculation**:
- 4,776,522 (trainable parameters) + 131,072 (PE buffer) = 4,907,594

### Explanation

The discrepancy is **resolved**:

- **4,776,522**: The correct count of trainable parameters (what `model.count_parameters()` returns)
- **4,907,594**: The total number of tensors in the state dictionary, including the positional encoding buffer (which is not a trainable parameter)

The `current.json` value of 4,776,522 is **correct** for the trainable parameter count. The checkpoint loading count of 4,907,594 includes the positional encoding buffer (131,072 elements), which PyTorch stores in the state dictionary but does not count as a trainable parameter.

### Conclusion

- ✅ Model architecture and checkpoint shapes are compatible
- ✅ `current.json` contains the correct trainable parameter count
- ✅ The discrepancy is explained by the inclusion of the positional encoding buffer in the state dict
- ⚠️ **Critical issue discovered**: `medium_transformer.py` has a broken import (line 55) that prevents instantiation

2. **Intent Classification** (lines 525-583): Pattern-based intent detection

## 5. Critical Issue Discovered

**Issue**: `packages/ai-core/neural/medium_transformer.py` has a broken import

**Location**: Line 55
```python
from .transformer import TransformerBlock
```

**Problem**: This import fails because `transformer.py` was renamed to `small_transformer.py` in Phase 1C, but `medium_transformer.py` was not updated.

**Impact**:
- MediumTransformer cannot be instantiated fresh
- ML service may fail at runtime when attempting to load the model
- The service may fall back to error handling instead of using the trained model

**Status**: This was **not** caught in the Phase 1C verification because:
1. The ML service can load the checkpoint without calling `__init__` (checkpoint loading uses `load_state_dict`)
2. The import only fails when attempting to instantiate MediumTransformer from scratch
3. The Phase 1C import verification only checked SmallTransformer and MediumTransformer imports, not instantiation

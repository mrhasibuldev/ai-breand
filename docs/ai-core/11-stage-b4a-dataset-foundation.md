## 3. Proposed Dataset Schema

### 3.1 Versioned Schema Design

**Schema Version**: v1.0  
**Purpose**: Structured Bengali-English and mixed-language conversations with provenance tracking

```json
{
  "version": "1.0",
  "metadata": {
    "created": "YYYY-MM-DD",
    "source": "original_project_collection | external_dataset_name | synthetic",
    "license": "CC-BY-4.0 | Apache-2.0 | MIT | custom | UNVERIFIED",
    "license_url": "https://...",
    "domain": "health_wellness | general_conversation | instruction_following",
    "languages": ["bengali", "english", "mixed"],
    "quality_reviewed": true,
    "reviewer": "reviewer_name_or_id",
    "review_date": "YYYY-MM-DD"
  },
  "conversations": [
    {
      "id": "conv_001",
      "messages": [
        {
          "role": "user | assistant",
          "content": "message text",
          "language": "bengali | english | mixed",
          "timestamp": "ISO-8601 if applicable"
        }
      ],
      "split": "train | validation | test",
      "tags": ["greeting", "health_question", "wellness_tip"],
      "quality_score": 0.0-1.0
    }
  ],
  "statistics": {
    "total_conversations": 0,
    "total_messages": 0,
    "language_distribution": {
      "bengali": 0,
      "english": 0,
      "mixed": 0
    },
    "split_distribution": {
      "train": 0,
      "validation": 0,
      "test": 0
    }
  }
}
```

### 3.2 Field Definitions

**Metadata Fields**:
- `version`: Schema version string (e.g., "1.0")
- `created`: ISO-8601 date of dataset creation
- `source`: Origin of data (project collection, external dataset, synthetic)
- `license`: SPDX identifier or description of license terms
- `license_url`: Link to license text if available
- `domain`: Primary domain (health/wellness, general, instruction-following)
- `languages`: List of languages present
- `quality_reviewed`: Boolean indicating manual review status
- `reviewer`: Identifier of person who reviewed data
- `review_date`: Date of quality review

**Conversation Fields**:
- `id`: Unique conversation identifier
- `messages`: Array of message objects
- `split`: Dataset split (train/validation/test)
- `tags`: Optional categorization tags
- `quality_score`: Optional 0-1 quality rating

**Message Fields**:
- `role`: "user" or "assistant"
- `content`: Message text
- `language`: Detected or annotated language
- `timestamp`: Optional timestamp for conversational data

**Statistics Fields**:
- `total_conversations`: Count of conversations
- `total_messages`: Count of all messages
- `language_distribution`: Counts by language
- `split_distribution`: Counts by split

### 3.3 Train/Validation/Test Separation Rules

**Separation Strategy**:
- Train: 80% of conversations
- Validation: 10% of conversations
- Test: 10% of conversations

**Separation Rules**:
1. **Conversation-level split**: All messages from a conversation stay in the same split
2. **Stratified by language**: Maintain language distribution across splits
3. **Stratified by domain**: Maintain domain distribution across splits
4. **No leakage**: User-level or session-level separation if applicable
5. **Random seed fixed**: Use fixed random seed for reproducibility

**Validation of Separation**:
- Verify no conversation appears in multiple splits
- Verify language distribution consistency
- Verify no duplicate conversation IDs across splits

### 3.4 Data Quality Requirements

**Minimum Quality Standards**:
- No empty messages
- No duplicate messages within a conversation
- Coherent conversational flow
- Appropriate language (no offensive content)
- Accurate language annotation
- PII removed or anonymized if present

**Quality Review Process**:
1. Automated checks (format, empty records, duplicates)
2. Manual review of sample (10% or minimum 100 conversations)
3. Language detection verification
4. Coherence check for conversation flow
5. Tag accuracy verification

## 4. Tokenizer Migration Design

### 4.1 Current SimpleTokenizer Analysis

**Implementation**: `packages/ai-core/tokenizer/tokenizer.py`  
**Type**: Word-level whitespace tokenization  
**Special Tokens**: PAD (0), UNK (1), BOS (2), EOS (3)  
**Current Vocabulary Size**: 74 tokens (active checkpoint)  
**Tokenization Method**: `text.lower().split()`  
**Limitations**:
- 74-token vocabulary is critically small
- Word-level tokenization inadequate for Bengali morphology
- No subword segmentation
- Bengali compound words treated as single tokens
- Unknown token rate likely high for unseen text

### 4.2 Proposed SentencePiece BPE Experiment

**Target Tokenizer**: SentencePiece (BPE)  
**Language Support**: Bengali, English, mixed-language  
**Target Vocabulary Size**: 2,000–5,000 tokens (experimental)  
**Special Tokens**: Preserve PAD, UNK, BOS, EOS IDs

#### 4.2.1 Special Token Handling

**Requirements**:
- PAD: ID 0 (padding)
- UNK: ID 1 (unknown)
- BOS: ID 2 (beginning of sequence)
- EOS: ID 3 (end of sequence)

**SentencePiece Configuration**:
```
pad_id=0
unk_id=1
bos_id=2
eos_id=3
user_defined_symbols=<pad>,<unk>,<bos>,<eos>
```

**Implementation Strategy**:
1. Prepend special tokens to training corpus before training SentencePiece
2. Configure SentencePiece to reserve IDs 0-3 for special tokens
3. Ensure vocabulary indices start at 4 for regular tokens

#### 4.2.2 Unicode and Bengali-English Mixed-Language Tests

**Test Cases**:
1. Pure Bengali text: "আমি বাংলায় কথা বলতে পারি"
2. Pure English text: "I can speak English"
3. Mixed sentence: "আমি English এবং Bengali দুই ভাষাতেই কথা বলতে পারি"
4. Code-switching: "আমি okay, এখন আসি"
5. Numbers: "১২৩" (Bengali numerals) vs "123" (Arabic numerals)
6. Punctuation: "আমি কি?" vs "What is it?"

**Expected Behavior**:
- Bengali Unicode characters handled correctly
- Mixed-language text tokenized without errors
- Bengali numerals recognized
- Punctuation handled appropriately

#### 4.2.3 Encoding/Decoding Round-Trip Tests

**Test Method**:
1. Encode test text using new tokenizer
2. Decode token IDs back to text
3. Compare original and decoded text
4. Measure character-level accuracy

**Acceptance Criteria**:
- Round-trip accuracy > 99% for test corpus
- No character loss for Bengali Unicode
- Special tokens preserved correctly
- Whitespace handling consistent

#### 4.2.4 Vocabulary Coverage and Unknown-Token Metrics

**Coverage Metrics**:
- Total tokens in training corpus
- Unique tokens in training corpus
- Vocabulary size
- Tokens covered by vocabulary
- Unknown token rate

**Measurement Plan**:
1. Train tokenizer on proposed dataset
2. Encode training corpus with new tokenizer
3. Count UNK tokens
4. Calculate unknown token rate: `UNK_count / total_tokens`

**Target Metrics**:
- Unknown token rate < 5% on training data
- Unknown token rate < 10% on validation data
- Vocabulary size appropriate for Bengali-English corpus

#### 4.2.5 Model Embedding/Output Dimensions

**Current Model**: MediumTransformer  
**Current Vocabulary Size**: 74  
**Current Embedding Dimension**: 256 (d_model)  
**Current Output Layer Dimension**: 256 → 74

**New Vocabulary Size**: 2,000–5,000 (experimental)  
**Required Changes**:
- Output layer: `nn.Linear(d_model, new_vocab_size)`
- Embedding layer: `nn.Embedding(new_vocab_size, d_model)`
- Checkpoint: Must include new vocabulary mapping

**Compatibility Requirements**:
- New checkpoint must include `tokenizer_vocab` field
- New checkpoint must include `vocab_size` metadata
- Old checkpoint remains unchanged (no migration)
- Inference code must handle both old and new checkpoints

#### 4.2.6 Checkpoint Versioning and Rollback

**Versioning Strategy**:
- Current checkpoint: `checkpoints_medium/final_model.pt` (v1.0, 74-token)
- Experimental checkpoint: `checkpoints_medium_v2.0.0_sp/final_model.pt` (v2.0.0, BPE)
- Rollback capability: Keep v1.0 checkpoint until v2.0.0 verified

**Checkpoint Metadata**:
```python
{
  "model_state_dict": dict,
  "tokenizer_vocab": dict,
  "metrics": dict,
  "vocab_size": int,
  "tokenizer_type": "simple | sentencepiece",
  "tokenizer_version": "1.0.0 | 2.0.0",
  "special_tokens": {"pad": 0, "unk": 1, "bos": 2, "eos": 3}
}
```

**Rollback Procedure**:
1. Keep v1.0 checkpoint in `checkpoints_medium/`
2. Add v2.0.0 checkpoint to new directory
3. Update ML service config to point to new checkpoint
4. If issues arise, revert config to v1.0
5. No destructive operations on v1.0

**Evaluation Metrics**:
- Coherence: Human-rated 1-5 scale
- Repetition: Count of repeated n-grams
- Unknown tokens: Count of UNK in generated text
- Length: Token count of generated response
- Language consistency: Does response match prompt language?

#### 5.1.2 Output Repetition Checks

**Metric**: Repetition Rate  
**Method**: Count repeated 2-grams, 3-grams, 4-grams in generated text  
**Baseline Target**: Measure current repetition rate for comparison

**Acceptance Threshold**: Repetition rate < 30% (current model likely exceeds this)

#### 5.1.3 EOS Stopping Checks

**Current Issue**: Generator does not check for EOS token  
**Test**:
1. Generate with max_new_tokens=50
2. Check if generation stops at EOS
3. Measure average tokens generated before EOS or max_tokens

**Expected Current Behavior**: Continues to max_tokens without EOS detection

#### 5.1.4 Unknown-Token Coverage

**Metric**: UNK token rate in generated text  
**Method**: Count UNK tokens / total tokens  
**Baseline Target**: Measure current UNK rate

**Expected Current Behavior**: High UNK rate due to 74-token vocabulary

#### 5.1.5 Latency and Memory Measurements

**Latency**:
- Measure inference time per prompt
- Average over 10 prompts
- Report seconds per prompt

**Memory**:
- Measure model memory footprint on load
- Measure peak memory during inference
- Report MB

**Mitigation**:
1. Run controlled experiments to verify hypothesis
